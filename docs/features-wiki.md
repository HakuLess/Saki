# MahjongCopilot 功能Wiki（参考原项目，KMP 版规划）

目标：先复刻 MahjongCopilot 的核心功能（不含自动打牌），并在 KMP（Kotlin Multiplatform + Compose Desktop）环境下给出实现规划与可行性评估。

## 核心功能点（不含自动打牌）
- 启动与登录：驱动客户端进入雀魂并保持会话。
- 游戏状态采集：实时抽取手牌、河牌、动作按钮、轮到谁、局/场信息等。
- 决策推理接入：支持本地 Mortal/Akagi 兼容模型与在线模型；三麻/四麻切换。
- 步进式建议展示：每一步给出推荐操作与简要原因。
- HUD 叠加层：在游戏界面顶部覆盖显示建议与高亮。
- GUI 设置面板：模型选择、3p/4p、权重路径或 API Key、语言、日志级别等。
- 多语言支持：中文/英文 UI 与 HUD 文案切换。
- 日志与诊断：采集/推理/渲染的行为与错误记录。
- 自动加入下一局（可选）：结算后自动点击进入下一局（不含自动出牌）。

## 步骤与可行性分析
- 启动与登录（可行性：高）
  - 方案：浏览器端用 Playwright 驱动 Chromium；KMP 版可用嵌入浏览器（JCEF/CEF）或外部浏览器并桥接。
  - 关键点：保持登录态（复用浏览器上下文/缓存）；进入对局房间后启动采集。
- 游戏状态采集（可行性：中-高）
  - 方案：DOM 选择器提取（手牌格、操作按钮、弃牌池）；必要时监听网络事件做校验。
  - 难点：选择器稳定性与版本变更；可加模板匹配兜底（OpenCV）。
- 决策推理接入（可行性：高）
  - 本地：加载 `libriichi`/`libriichi3p`，按 MJAI 协议转换 `GameState` 输入/输出。
  - 在线：HTTP/WebSocket 按在线服务接口调用；配置 `url` 与 `api_key`。
  - 要点：强制 3p/4p 与房间类型一致；模型未就绪时给予提示与回退。
- 步进式建议展示（可行性：高）
  - 方案：每次状态变更触发推理，生成推荐与解释；提供“速度/打点/安全性”维度的简要文案。
  - 要点：异步队列与节流，避免过时状态与抖动。
- HUD 叠加层（可行性：高）
  - 方案：在页面注入固定 `div` 作为 overlay，绝对定位、`pointer-events:none`；
  - 要点：根据 DOM 元素坐标高亮推荐牌与可操作按钮；避免遮挡核心交互区。
- GUI 设置面板（可行性：高）
  - KMP 版：使用 Compose Multiplatform Desktop 构建设置窗口；
  - Python 原型：tkinter/Qt 快速验证；
  - 要点：配置持久化（JSON/YAML），热更新模型与采集策略。
- 多语言支持（可行性：高）
  - 方案：i18n 映射表（JSON），HUD/GUI 文案统一走翻译函数；默认中文，支持英文。
- 日志与诊断（可行性：高）
  - 方案：统一日志（debug/info/warn/error），采集/推理/渲染链路的关键事件与错误；
  - 要点：提供“导出日志”与“显示原始采集数据”面板便于排障。
- 自动加入下一局（可行性：中）
  - 方案：监听结算页面 DOM，识别“继续/加入下一局”按钮并点击；
  - 要点：按钮定位容错与重试；避免误操作。

## KMP 版架构建议
- `app-desktop`：Compose Desktop UI（设置面板、状态概览）。
- `hud-overlay`：叠加层渲染（如嵌入浏览器或透明窗体叠加）。
- `engine-collector`：采集模块（外部浏览器 + 桥接 或 JCEF 嵌入）；
- `engine-bot`：模型接口（本地 `libriichi`/在线服务）；
- `common-mjai`：MJAI 数据结构与协议适配；
- `bridge`：与采集/推理的通信（WebSocket/gRPC/本地进程消息）。

## 依赖与配置
- 浏览器/采集：Playwright（原型）或嵌入式浏览器；
- 模型：`libriichi`/`libriichi3p`（本地）或在线服务；
- 配置：`config.json`（模型类型、3p/4p、API Key、日志级别、语言）。

## 风险与对策
- 选择器变更：建立选择器回归测试与兜底模板匹配；
- 3p/4p错配：在房间进入前强制校验模型与模式一致；
- 性能抖动：推理调用节流，HUD 合并更新；
- 合规性：遵循 AGPL-3.0（Mortal）与 GPLv3（Akagi/Copilot）的使用与分发条款。

## 里程碑建议
- M1：采集与 HUD 打通（浏览器端原型，中文 HUD）。
- M2：接入本地 Mortal 模型（3p/4p），GUI 设置与持久化。
- M3：在线模型与日志/诊断完善，i18n 支持。
- M4：KMP 版 GUI/HUD 重构与桥接整合，自动加入下一局（可选）。
