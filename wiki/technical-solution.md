# 雀魂游戏AI助手技术方案评估

## 1. 架构设计方案

### 核心架构
- **多平台共享模块**：使用Kotlin Multiplatform在commonMain中定义接口和数据模型
- **平台特定实现**：在desktopMain中实现Windows平台的具体功能
- **分层设计**：
  - 数据层：模型加载和管理
  - 业务层：游戏分析和决策逻辑
  - 接口层：UI交互和自动操作
  - 平台层：系统API调用

### 模块划分
1. **MahjongAIService接口**：定义AI服务的核心功能
2. **数据模型**：定义游戏状态、动作类型等
3. **Windows实现**：使用JNA调用Windows API
4. **模型加载器**：加载和使用mortal.pth模型
5. **图像识别模块**：分析游戏画面
6. **UI组件**：用户交互界面

## 2. 技术选型与可行性评估

### 2.1 屏幕捕获与图像处理
- **技术方案**：使用JNA调用Windows GDI API或Java Robot类
- **可行性**：★★★★★
  - Java Robot类提供了跨平台的屏幕捕获能力
  - JNA可直接调用Windows原生API，性能更好
  - 已在多个项目中验证可用

### 2.2 游戏状态获取方案

#### 2.2.1 网络请求拦截方案
- **技术方案**：
  - 拦截雀魂客户端的网络请求
  - 解析JSON格式的牌谱数据
  - 直接获取结构化的游戏状态信息
- **可行性**：★★★★★
  - 基于MahjongCopilot的成功实践
  - 获取的数据完全准确，避免视觉识别误差
  - 性能更高，无需图像处理开销
- **实现方式**：
  - 使用JNA调用系统API进行网络代理或钩子
  - 或集成Playwright等自动化工具拦截请求
  - 解析雀魂特有的数据格式

#### 2.2.2 图像识别方案（备选）
- **技术方案**：
  - OpenCV用于图像处理和特征提取
  - 模板匹配识别麻将牌
  - OCR识别得分和状态信息
- **可行性**：★★★★☆
  - OpenCV在Kotlin中通过JNA/JNI绑定可用
  - 麻将牌识别是相对成熟的计算机视觉问题
  - 需要针对雀魂界面进行专门的模板训练
- **适用场景**：
  - 当网络请求拦截不可用时的备选方案
  - 需要分析视觉界面元素时使用

#### 2.2.3 方案比较

| 特性 | 网络请求拦截 | 图像识别 |
|------|------------|----------|
| 准确性 | ★★★★★ | ★★★☆☆ |
| 性能 | ★★★★★ | ★★☆☆☆ |
| 实现复杂度 | ★★★☆☆ | ★★★★☆ |
| 抗干扰性 | ★★★★★ | ★★☆☆☆ |
| 版本适配性 | ★★☆☆☆ | ★★★★☆ |

**结论**：网络请求拦截方案明显更准确、高效，应作为首选方案。但需要注意，随着游戏版本更新，API结构可能变化，需要及时适配。

### 2.3 AI决策引擎
- **技术方案**：
  - 加载PyTorch模型(mortal.pth)
  - 或使用与Mortal兼容的Java/Kotlin实现
- **可行性**：★★★☆☆
  - 直接在JVM中加载PyTorch模型需要LibTorch绑定
  - 可以考虑使用ONNX格式转换模型
  - 或者通过子进程调用Python服务处理模型推理

### 2.4 自动化操作
- **技术方案**：
  - JNA调用Windows API模拟鼠标点击
  - 或使用Java Robot类
- **可行性**：★★★★★
  - Windows API提供了完整的输入模拟能力
  - 可精确定位游戏窗口和按钮位置
  - 需要处理不同分辨率和窗口缩放的情况

### 2.5 KMP架构集成
- **技术方案**：
  - 共享业务逻辑和数据模型
  - 平台特定代码处理系统交互
- **可行性**：★★★★★
  - KMP架构非常适合这种需求
  - Compose Multiplatform提供了统一的UI框架
  - 可以轻松扩展到其他平台

## 3. 实施步骤与风险分析

### 阶段三：AI决策集成

## 4. 技术挑战与解决方案

1. **模型加载**：
   - 挑战：PyTorch模型在JVM中的加载
   - 解决方案：使用ONNX Runtime或通过Python进程通信

2. **网络请求拦截稳定性**：
   - 挑战：雀魂可能更改API结构或加密方式
   - 解决方案：实现API版本检测与适配机制、构建灵活的数据解析框架、添加日志系统便于问题诊断

3. **游戏更新适配**：
   - 挑战：雀魂更新可能改变网络请求格式
   - 解决方案：设计松耦合的数据模型转换层、实现配置驱动的解析规则、建立API变化监测机制

4. **权限与安全限制**：
   - 挑战：系统可能限制网络请求拦截
   - 解决方案：使用多种拦截方法（代理/钩子/内存读取）、实现降级到图像识别的备选方案、符合相关软件使用规范

## 5. 总结

基于Kotlin Multiplatform技术栈实现雀魂游戏AI助手是完全可行的。技术方案已优化为优先采用网络请求拦截获取牌谱信息，相比传统的图像识别方案具有显著优势。

项目核心优势：
- **准确性**：网络请求拦截方案提供100%准确的牌谱数据，避免了图像识别可能带来的误差
- **性能**：直接解析结构化数据，大幅降低计算开销，实现实时响应
- **架构灵活性**：KMP架构实现代码最大化复用，同时保留对平台特定功能的访问能力
- **鲁棒性**：设计了网络拦截和图像识别两套方案，确保系统稳定性和适应性
- **决策质量**：结合Mortal模型的强大决策能力，提供高质量的对局指导

项目实施分为五个清晰的阶段，从基础架构到最终集成，每一步都有明确的目标和挑战。虽然存在API适配、权限限制等技术挑战，但通过已设计的解决方案，可以有效应对这些挑战，确保项目成功实施。网络请求拦截方案的采用将使整个系统更加高效、准确和用户友好。
